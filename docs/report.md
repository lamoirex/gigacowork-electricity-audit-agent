# Сверка начислений за электроэнергию
Контрольный отчёт • Фабрика решений

Задача сотрудника — проверить начисления, сопоставив расход и сумму без НДС с нормативом магазина за тот же месяц. На выходе доступны книга Excel и черновик уведомления.

## Вопросы к заказчику

1. **Специалист по нормативам.** Как выбирать версию, если норматив обновился в середине месяца? От ответа зависит база сравнения. До уточнения берём последнюю версию, действовавшую на первое число, при совпадении даты выбираем больший числовой номер.
2. **Сотрудник проверки.** Нужно ли пересчитывать норматив пропорционально неполному месяцу? Это меняет статус частичного начисления. Пока направляем такую строку на ручную проверку.
3. **Руководитель направления.** Каков порог и достаточно ли превышения по одному показателю? Это определяет состав очереди проверки. Пока используем строго более 10% по энергии или сумме.
4. **Супервайзер.** Какие суммы сопоставимы по НДС? Несопоставимые суммы создадут ложные превышения. Используем рубли без НДС.
5. **Сотрудник проверки.** Как регистрировать повтор перерасчёта? Ответ определяет причину и число исключений. Первую запись считаем перерасчётом, повтор с тем же ключом считаем дублем.
6. **Руководитель направления.** Как учитывать закрытый магазин с действующим нормативом? От ответа зависит охват проверки. До согласования сверяем его на общих основаниях.

## Правила и расчёт

1. нет ID магазина / периода / потребления — **требуется уточнение**
2. магазин не найден в справочнике (после нормализации ID) — **требуется уточнение**
3. дубль: магазин + период + номер документа + тип — **исключение: дубль**
4. тип начисления = «Перерасчёт» — **исключение: перерасчёт**
5. даты не покрывают календарный месяц — **исключение: неполный месяц**
6. нет активной версии норматива на магазин + период — **требуется уточнение**
7. единицы начисления и норматива не совпадают — **требуется уточнение**
8. всё полное: сравнение без НДС, порог строго больше 10% по кВт·ч или по сумме — **превышение / в норме**

### Выбор версии норматива
1. Фильтр по магазин + период.
2. Оставляем версии, у которых Действует с <= 1-е число периода.
3. Сортируем по Действует с, при равенстве — по номеру версии.
4. Берём последнюю.

### Алгоритм работы скрипта
1. На листах каждой книги ищем строку заголовков по синонимам. При нескольких подходящих листах запрашиваем однозначную выгрузку.
2. Для каждой строки начислений сохраняем номер строки источника. Применяем правила таблицы сверху вниз. Для правил 1–7 записываем причину в реестр, расчётные поля оставляем пустыми.
3. Для правила 8 считаем разность факта и норматива по энергии и сумме без НДС. Процент равен разности, делённой на норматив и умноженной на 100. При нулевой базе процент пуст, положительная разность даёт превышение. Месяц входит в ключ выбора сезонного норматива.
4. Записываем все решения в журнал и лист отклонений. Формируем счётчики, причины и черновик уведомления. Сотрудник получает книгу и проверяет отмеченные строки.

## Допущения

* Порог 10% хранится в `references/params.json`, меняется без правки кода.
* Суммы сравниваются без НДС.
* При нескольких версиях норматива берём последнюю активную на 1-е число периода.
* Единицы нормализации: `кВт·ч`, `kWh`, `квтч`, `кВт*ч` — эквивалентны. `кВт` — мощность, не эквивалент, уходит в «требуется уточнение».
* ID магазина нормализуется: trim, casefold, удаление пробелов и знаков. Ведущие нули снимаются только у полностью цифрового ID.
* Дубли определяются по кортежу (магазин, период, документ, тип) — первая строка в расчёт, остальные в реестр.
* Перерасчёт и неполный месяц в сверку не идут — ручное решение.

Основной набор содержит 28 начислений за январь–март 2025 года, 26 строк нормативов и 8 магазинов. Включены ровно 10% и 10,01%, нулевой норматив, неверная единица норматива, разные написания ID, пропуски, дубль и конкурирующие версии. Ожидаемые решения заданы генератором независимо от скрипта навыка.

Дополнительные наборы проверяют чужие заголовки на 2 строках и комбинации правил на 90 строках. В каждом наборе используется один и тот же вход для трёх повторов. Архив `testdata.zip` содержит основной набор, разметку и генератор.

## Метод измерения

Для каждой строки проверяются значения или ожидаемая пустота, причина, журнал и принадлежность реестру. Подстановка — заполненная ячейка вместо ожидаемой пустой среди входных и расчётных полей. Стабильность определяется по SHA-256 содержимого всех листов. Порог точности — 95%, форма — 100%, допустимых подстановок — 0.

В режиме API скрипт читает три книги, сохраняет Excel и передаёт модели синтетическую сводку для краткого ответа по шаблону. Время включает обработку файлов и ожидание API. Локальный режим измеряет только CLI. Отдельным этапом остаётся проверка пустого сообщения с вложениями в интерфейсе GigaCowork.
