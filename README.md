# Агент проверки коммунальных платежей (GigaCowork)

Тестовое задание «Фабрики решений»: AI-агент для GigaCowork, который по трём выгрузкам Excel (начисления за электроэнергию, нормативы потребления, справочник магазинов) сверяет каждое начисление с действующим нормативом, определяет статус строки (в норме, превышение, исключение, требуется уточнение), объясняет каждый флаг и готовит текст уведомления ответственному сотруднику.

> **Решения принимает детерминированный скрипт, модель только запускает его и пересказывает результат.** Поэтому результат воспроизводим, объясним и не содержит выдуманных значений. Превышение норматива — сигнал к проверке, а не доказанная переплата.

| Метрика из БТ | Порог | Результат (28 строк × 3 прогона) |
| --- | --- | --- |
| Точность (статус, отклонения кВт·ч / руб. / %, причина) | ≥ 95% | **100%** |
| Форма результата: 3 листа, 13 колонок в заданном порядке | 100% прогонов | **100%** |
| Выдуманные значения на ловушках (нет норматива, периода, единицы) | 0 | **0** |
| Воспроизводимость трёх запусков | одинаково | **одинаково** |
| Обоснование у каждого флага: что с чем сравнено | да | **да** |
| Время ответа агента | ≤ 60 с | **~8-10 с** (скрипт **~0.2 с**) |

Подробно — в `runs/REPORT.md`. Эталон задан **вручную** по каждой строке начислений (`testdata/generate.py`), а не получен прогоном самого агента: иначе 100% ничего бы не доказывали.

## Быстрый старт

```bash
pip install -r requirements.txt
python3 testdata/generate.py
python3 agent/skill/utility-check/scripts/check_charges.py \
        testdata/out/charges.xlsx testdata/out/norms.xlsx testdata/out/stores.xlsx ./result
python3 tools/evaluate.py result/reconciliation.xlsx testdata/out/expected.json
```

Скрипту можно передать файлы в любом порядке или папку с ними. Роль каждого файла определяется по заголовкам, имена файлов и листов не важны.

## Как пользоваться в GigaCowork

1. Загрузить навык (zip) и системный промпт `system_prompt.txt` (оба — в `dist/agent.zip`, см. `agent/INSTALL.md`).
2. Выбрать агента, приложить три выгрузки и отправить **пустое** сообщение.
3. Получить Excel-файл и короткий ответ в чат.

## Листы результата

| Лист | Что внутри |
| --- | --- |
| «Отклонения» | Все строки со статусом, 13 колонок в заданном порядке: ID магазина; Период; Потребление, кВт·ч; Начислено без НДС, руб.; Норматив, кВт·ч; Норматив, руб.; Версия норматива; Отклонение, кВт·ч; Отклонение, % (кВт·ч); Отклонение, руб.; Отклонение, % (руб.); Статус; Обоснование |
| «Реестр исключений» | Строки без сверки: дубли, перерасчёты, неполные месяцы и «требуется уточнение», с причиной и действием для человека |
| «Журнал решений» | По каждой исходной строке: номер сработавшего правила и основание |

## Правила проверки

Каждая строка проверяется по порядку, первое сработавшее условие определяет статус.

| № | Условие | Статус |
| --- | --- | --- |
| 1 | Нет ID магазина, периода или потребления | Требуется уточнение |
| 2 | Магазин не найден в справочнике | Требуется уточнение |
| 3 | Дубль: совпадают магазин, период, документ и тип | Исключение: дубль |
| 4 | Тип начисления «Перерасчёт» | Исключение: перерасчёт |
| 5 | Неполный месяц | Исключение: неполный месяц |
| 6 | Нет норматива на магазин и период | Требуется уточнение |
| 7 | Несовпадение единиц (кВт и кВт·ч) | Требуется уточнение |
| 8 | Превышение / В норме (порог **строго больше 10%**) | Превышение / В норме |

Действующая версия норматива — последняя с датой начала не позже первого дня периода. Порог хранится в `references/params.json` и меняется без правки кода.

## Структура репозитория

```text
agent/
  system_prompt.txt                  системный промпт агента
  INSTALL.md                         установка и запуск
  skill/utility-check/               навык в формате GigaCowork
    SKILL.md                         когда применять, как запустить, как ответить
    scripts/                         Python 3 (stdlib, openpyxl)
    references/                      параметры правил (порог, синонимы)
docs/
  customer_questions.md              вопросы заказчику
  algorithm.md                       алгоритм и допущения
  report.md                          отчёт (из него собирается PDF)
testdata/
  generate.py                        генератор синтетики; эталон задан вручную
  scenarios/                         дополнительные генераторы
tests/                               тесты
tools/
  evaluate.py                        метрики относительно эталона
runs/                                результаты прогонов + REPORT.md
build_skill.py                       сборка agent.zip и testdata.zip
requirements.txt · requirements-dev.txt
```
